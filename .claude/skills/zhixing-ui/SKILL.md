# 知行 UI Skill

## 这是什么

把知行的界面**做得更统一、更耐看、更好用**，而不是换一套别的风格。

它由两层组成：

1. **打磨流程**（本文件）—— 一套可重复的审计与实施方法，任何页面、任何主题下都适用。
2. **知行的设计语言**（`references/design-system.md`）—— 具体规格：两平面的令牌、质感配方、动效参数、组件尺寸。**决定要动视觉时再读它。**

> 与外部风格的取舍：可以参考别人（比如 Summer Checkin 那套深色玻璃）的**做法与工艺**，
> 但**产物必须是知行的**——令牌、色相、组件尺寸都回到本 skill 的规格，不要照搬别人的色板。

---

## 范围

**在范围内**：布局与间距、视觉层级、配色与对比、字体与排版、控件与状态、响应式、动效打磨、无障碍。

**不在范围内**：业务逻辑、数据模型、接口、路由、功能增减、换框架。

**绝对禁区（改了就出事）**：

| 禁区 | 为什么 |
|---|---|
| `src/components/resume-editor.tsx` 的 `pageCss()`（8 套模板 + 打印 CSS） | 这是**功能**不是装饰：改一下导出 PDF 就串版 |
| `contentEditable` 相关的 DOM 操作、撤回/恢复快照栈 | 内容以 DOM 为准，改动会破坏撤回 |
| `src/proxy.ts`、`src/lib/dal.ts` 的鉴权分支 | 安全边界 |
| `prisma/`、`Dockerfile`、`docker-compose.yml`、`.github/` | 不属视觉层 |
| Tailwind 的 `@theme inline` 里 indigo/violet → `--accent` 的映射 | 拆了等于全站主题色换色失效 |

## 工作流

按顺序来。**不要一上来就写样式。**

### 0. 先定平面（lane），再动手

知行的界面分两个平面，**它们的视觉语言不一样，别混**：

| 平面 | 页面 | 语言 | 令牌 |
|---|---|---|---|
| **A · 展示页（surface）** | `/` 落地页、`/about`、`/s/[id]` 公开分享页 | **深色玻璃场景**：单一强调色、玻璃面板、环境顶光、克制动效 | `--theme-*`（16 个，作用域 `.zx-landing`） |
| **B · 工具页（workspace）** | `/dashboard`、`/kb/*`、`/resume`、`/jobs/*`、`/workbench/*`、`/settings`、`/admin/*` | **克制、密集、实用**：浅/深双主题、跟随用户主题色、柔和阴影、不做玻璃不做噪点 | `--accent*`、`--background`、`--foreground` |

**先问清楚是哪一档**，一次问完，别中途反复：

- **改展示页** → 走 A 面规格。保持深色场景，**不跟随用户主题色**（落地页是"知行的脸"，永远同一个品牌印象）。
- **改工具页** → 走 B 面规格。必须**同时验证浅色与深色两种主题**，并且**跟随 `--accent`**（用户可以在设置里换 8 套主题色）。
- **只想小修** → 保持现有风格，只在自己已有的令牌里修，不动结构。

> 判断依据：**这一页是给「陌生人看一眼」的，还是给「自己天天用」的？**
> 前者可以表达（A），后者必须实用（B）。工具页塞玻璃和摄影背景 = 看不清数据、更慢。

### 1. 理解这一页在干什么

- 这是**工作界面**还是**展示界面**？（决定走 A 还是 B）
- 读代码，先搞清楚现有的令牌与组件约定：`globals.css` 里的 `--accent*`、`.app-bg`、`.card-soft`，以及 A 面的 `.zx-*`。
- 找出**主路径**：用户在这一页最常做的动作是什么？先优化它。

### 2. 用这张清单审计

打开真实渲染结果（**桌面 + 手机都要看**），记**具体缺陷**，不要写"感觉不太行"。

**布局与结构**
- 区块是全宽带 + 受约束的内容区，还是每块都套成浮动卡片？**绝不允许卡片套卡片。**
- 卡片只用于：重复项、弹窗、真正需要框起来的工具（聊天气泡、指标、列表行）。
- `min-w-0` / `flex-1` / 响应式栅格到位，flex 子项**收缩而不是溢出**。
- 固定几何元素（按钮、chip、计数、徽章）**尺寸固定**，不会因为文字变长而跳动。

**层级与密度**
- 一屏**只有一个主操作**，次级操作视觉上明确退后。
- 标题／正文／弱化标签层级分明，不是全一个字号。
- 工具页要**密而可扫**：不要超大 hero、不要装饰性卡片堆。

**排版**
- 用现有字号阶梯；密集面板 `text-xs`~`text-sm`，hero 档只留给真正的首屏。
- 数字、计数、时间戳、眉标、代码一律走**等宽 + `tabular-nums`**，保证列不跳动。
- 长标签截断并给出完整值的提示；文字**永不裁切、溢出、压到兄弟元素**。

**配色与对比**
- **不要单一色相统治整页**；不要紫蓝渐变统治、不要米色/沙色统治、不要深蓝板岩色统治。
- **一个主强调色，克制使用**。整页一个强调色 = 没有层级。
- 正文与弱化文字对比度必须够读。**优先用语义令牌，不要写死 hex。**

**控件与可供性**
- 图标按钮要有 `aria-label` + 主题化 tooltip。
- 控件匹配意图：模式用分段控件、二值用开关、数值用滑块/步进、选项用菜单、视图切换用 tab。
- 每个可交互元素都有 **hover / focus-visible / active / disabled** 四态；空态、加载态、错误态都要有。

**动效**
- 全状态齐备：hover / focus 150–200ms，`:active` 缩放到 `0.97`，focus ring 用主色。
- 主题色切换：只动**颜色族属性**，380ms，`cubic-bezier(.4,0,.2,1)`，**布局不参与动画**。
- **不要渐变光球、散景斑点、装饰性循环动画。**
- **必须**尊重 `prefers-reduced-motion`：过渡归零、reveal 立即点亮、内容绝不永久隐藏。

**响应式**
- 手机端不要让次要操作只能靠 hover 才能发现。
- 触控目标加宽松，但**状态规格不放大**。

### 3. 排优先级

1. 布局破损、溢出、重叠、无障碍问题（对比、标签、焦点、点击区域）。
2. 结构与排版问题 —— 那些让主任务变难的东西。
3. 控件、状态、交互打磨。
4. **最后**才是配色和首屏构图。

**宁可少改几处高价值的，也不要做大范围表面翻新。** 顺手重构无关代码 = 禁止。

### 4. 按平面实施

**A 面 · 展示页** —— 按 `references/design-system.md` §8 的版式搭：固定背板 + 暗过渡 veil + 胶片噪点，
内容用玻璃面板承载；主色自发光按钮；滚动 reveal 带错峰。**零外链图片**（用内联 SVG 背板，避免 CORS/ORB 导致首屏空白）。

**B 面 · 工具页** —— 按 §7 的组件规格搭：语义令牌供料（`--accent*` / `--background` / `--foreground`），
1px 边框 + 柔和阴影，hover 微浮起（`.card-soft` 已经是这个规格，**优先复用它**），
状态用主色的低透明度柔底。**不做玻璃、不做噪点、不做摄影背板。**
桌面 `.app-bg` 提供柔和渐变底，手机端不要为了渐变牺牲可读性。

### 5. 收尾必查

- 渲染出来截图看：**非空白、构图正确、没有重叠**。
- 各视口检查文字是否裁切/溢出。
- 主流程在桌面和手机各走一遍，包含 hover / focus / 空 / 禁用 / 错误态。
- 确认控件不会位移，按钮与层级稳定。
- `prefers-reduced-motion: reduce` 下重走主流程：**全部立即显示，没有内容永久隐藏**。
- **B 面必须浅色和深色两种主题都验一遍**，并且至少换一个非默认主题色（如翠绿/粉色）确认没有硬编码颜色露出来。
- 跑 `node node_modules/typescript/bin/tsc --noEmit`，必须 `exit 0`。
